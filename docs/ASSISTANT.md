# Ассистент по документации

Ассистент отвечает на вопросы о проекте, опираясь на **содержимое самого
портала**, а не на память модели. Эта страница объясняет, что он умеет, чем
ограничен и как его включить.

## 1. Почему это Mastra, а не Dify

В документации квеста AI-слой — это Dify ([`projectDocs.ts`](../src/data/projectDocs.ts)),
и для LLMOps-пайплайнов он остаётся правильным выбором: черновики биографий,
RAG по архивам, визуальный конструктор промптов.

Ассистент портала — другая задача: маленький агент с тремя инструментами,
который должен жить **внутри TypeScript-сервиса**, делить типы с остальным кодом
и не требовать отдельного развёртывания. Mastra даёт именно это — библиотека, а
не платформа. Держать обе системы значило бы иметь две агентские платформы без
причины.

## 2. Откуда агент берёт знания

Корпус собирается из тех же данных, что рендерит страница
([`src/agent/corpus.ts`](../src/agent/corpus.ts)):

| Источник | Что даёт |
|---|---|
| `DOC_SECTIONS` | 12 разделов с подразделами, назначением и аудиторией |
| `REST_ENDPOINTS` | эндпоинты с методами и списком разрешённых ролей |
| `RBAC_ROLES` + `RBAC_MATRIX` | роли и их фактические права по коллекциям |
| `TECH_STACK`, `DEV_ENDPOINTS` | технологии и локальные адреса сервисов |

Следствие: если добавить раздел в `DOC_SECTIONS`, ассистент сразу сможет на него
ответить. Ни переиндексации, ни отдельного шага, который можно забыть.

## 3. Инструменты

| Инструмент | Назначение |
|---|---|
| `searchDocumentation` | Поиск по всем источникам, возвращает фрагменты с оценкой |
| `listApiEndpoints` | Список эндпоинтов, с фильтром по роли |
| `getRolePermissions` | Права конкретной роли; при неизвестной роли вернёт список допустимых |

Поиск — взвешенный по совпадению слов, а не эмбеддинги. Причина: корпус это
несколько сотен записей, поэтому такой поиск мгновенный и детерминированный, не
требует ключа и не даёт ложных «семантических» совпадений. Если корпус вырастет
до тысяч фрагментов, замена на векторное хранилище затрагивает только
`src/agent/tools.ts`.

**Пустой результат обрабатывается явно.** Инструмент возвращает подсказку
«ничего не найдено, не придумывайте ответ» — это дешевле, чем бороться с
галлюцинациями на уровне промпта.

## 4. Включение

```bash
LLM_API_KEY=sk-...        # обязательно
LLM_MODEL=deepseek-chat   # по умолчанию
LLM_BASE_URL=             # опционально: свой OpenAI-совместимый endpoint
```

Без ключа `POST /api/assistant/ask` отвечает **503** с перечнем нужных
переменных. Это осознанно: молчаливый пустой ответ или 500 заставляли бы гадать,
сломан ассистент или выключен.

```bash
curl -s -X POST localhost:3000/api/assistant/ask \
  -H 'content-type: application/json' \
  -d '{"question":"Какие роли могут погасить приглашение?"}'
```

```json
{ "ok": true, "answer": "Приглашение погашают Event Manager и Admin — эндпоинт POST /items/invitations/{id}/redeem." }
```

## 5. Ограничения и безопасность

- **Ограничение частоты — 10 запросов в минуту на IP.** Каждый вопрос стоит
  денег у провайдера; без лимита анонимный клиент мог бы опустошить счёт.
- **Длина вопроса ограничена 1000 символами** по той же причине.
- **Ключ только на сервере.** Клиентский бандл ассистента не содержит: сборка
  проверяется бюджетом и тестом на отсутствие `mastra` в `dist`.
- **Промпт запрещает выдумывать.** Пятое правило инструкций прямо требует
  отвечать «в документации этого нет», а инструмент при пустом результате
  возвращает такую же подсказку.
- **Промпт-инъекции.** Агент работает только с документацией проекта и не имеет
  инструментов, меняющих состояние: даже успешная инъекция не даёт доступа к
  файлам, сети или git.

## 6. Тестирование

`src/tests/agent.test.ts` покрывает три уровня:

1. **Корпус** — что он собран из настоящих данных и содержит ожидаемые роли,
   эндпоинты и права.
2. **Поиск** — что реальные вопросы («какие роли могут погасить приглашение»)
   находят реальные ответы, а посторонние («квантовая хромодинамика») дают ноль.
3. **Сборка агента** — что инструменты регистрируются; несоответствие схемы
   падает при конструировании, а не на первом вопросе пользователя.

Тесты не обращаются к провайдеру модели: агент собирается с подставной моделью,
поэтому набор проходит без ключа и без сети.

## 7. Чего здесь нет

Честно о границах реализации:

- **Нет памяти диалога.** Каждый вопрос независим. Для многошагового разговора
  нужен `Memory` из Mastra и хранилище — это отдельное решение.
- **Нет стриминга.** Ответ возвращается целиком. SSE потребовал бы изменений
  в клиенте.
- **Нет UI в портале.** Эндпоинт есть, страница с чатом — нет. Интерфейс
  добавляется как отдельная задача; сейчас ассистент доступен через API и Scalar.
- **Нет оценки качества (evals).** Mastra предоставляет `evals`, но настраивать
  их имеет смысл после появления реальных вопросов и логов.
