# API

Портал документации AR-квеста «Первооткрыватели Прикамья».

Документ генерируется из Zod-схем (`src/server/schemas.ts`) и типов контракта
(`src/shared/apiContract.ts`). Ручная правка спецификации невозможна по замыслу:
источник правды — код, и расхождение ломает сборку.

Все ошибки возвращаются в формате `application/problem+json` (RFC 7807).
Каждый ответ несёт заголовок `X-Request-Id`, который повторяется в теле ошибки.

**Версия:** 1.0.0 · **OpenAPI:** 3.1.0

Интерактивная версия: `/api/docs` (Scalar). Машиночитаемая: `/api/openapi.json`.

## Маршруты

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | Проверка живости |
| `GET` | `/api/git/status` | Состояние рабочего дерева |
| `POST` | `/api/git/commit-push` | Коммит и пуш изменений |
| `POST` | `/api/assistant/ask` | Вопрос по документации |

## Подробности

### `GET /api/health`

**Проверка живости**

Используется HEALTHCHECK контейнера и внешним мониторингом. Не требует авторизации.

**Ответы:**

| Код | Описание |
|---|---|
| `200` | Сервис работает |

### `GET /api/git/status`

**Состояние рабочего дерева**

Ветка, remote, список изменённых файлов и последние коммиты. URL remote проходит через редактор секретов, поэтому встроенные учётные данные не возвращаются.

**Ответы:**

| Код | Описание |
|---|---|
| `200` | Текущее состояние репозитория |
| `500` | Не удалось прочитать состояние репозитория |

### `POST /api/git/commit-push`

**Коммит и пуш изменений**

Стейджит все изменения, создаёт коммит и отправляет в origin.

Ограничение частоты: **5 запросов в 30 секунд на IP**. При превышении
возвращается 429 с заголовком `Retry-After`.

Если в индекс попал файл `.env*`, коммит отменяется целиком (код 409):
выборочное снятие с индекса оставляло бы варианты, о которых забыли.

**Тело запроса** (`application/json`):

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "properties": {
    "message": {
      "type": "string",
      "maxLength": 200
    }
  },
  "additionalProperties": false
}
```

Пример:

```json
{
  "message": "docs: обновление документации портала"
}
```

**Ответы:**

| Код | Описание |
|---|---|
| `200` | Коммит создан (или не требовался) и отправлен |
| `400` | Тело запроса не прошло валидацию |
| `401` | Для отправки нужен GITHUB_TOKEN |
| `409` | В индекс попал файл окружения — коммит отменён |
| `429` | Превышено ограничение частоты |
| `500` | Ошибка git или файловой системы |

### `POST /api/assistant/ask`

**Вопрос по документации**

Отвечает на вопросы о проекте, опираясь на содержимое самого портала
(разделы, API-эндпоинты, роли RBAC, технический стек).

**Требует настройки.** Если `LLM_API_KEY` не задан, эндпоинт отвечает 503
с перечнем нужных переменных — а не молчаливым пустым ответом.

Ограничение частоты: **10 запросов в минуту на IP**, потому что каждый
запрос стоит денег у провайдера модели.

**Тело запроса** (`application/json`):

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "properties": {
    "question": {
      "type": "string",
      "minLength": 2,
      "maxLength": 1000
    }
  },
  "required": [
    "question"
  ],
  "additionalProperties": false
}
```

Пример:

```json
{
  "question": "Какие роли могут погасить приглашение?"
}
```

**Ответы:**

| Код | Описание |
|---|---|
| `200` | Ответ, основанный на документации |
| `400` | Тело запроса не прошло валидацию |
| `429` | Превышено ограничение частоты |
| `502` | Провайдер модели недоступен |
| `503` | Ассистент не настроен (нет LLM_API_KEY) |

## Формат ошибок

Все ошибки — `application/problem+json` (RFC 7807):

```json
{
  "type": "object",
  "required": [
    "type",
    "title",
    "status",
    "detail",
    "error"
  ],
  "properties": {
    "type": {
      "type": "string",
      "description": "URI, идентифицирующий тип проблемы"
    },
    "title": {
      "type": "string",
      "description": "Краткое описание проблемы"
    },
    "status": {
      "type": "integer",
      "description": "HTTP-код ответа"
    },
    "detail": {
      "type": "string",
      "description": "Человекочитаемое объяснение"
    },
    "instance": {
      "type": "string",
      "description": "URL запроса, на котором произошла ошибка"
    },
    "error": {
      "type": "string",
      "description": "Сообщение об ошибке (совместимо с прежним API)"
    },
    "details": {
      "description": "Машинночитаемые детали, например список проблем валидации"
    },
    "requestId": {
      "type": "string",
      "description": "Идентификатор запроса; повторяется в заголовке X-Request-Id"
    }
  }
}
```
