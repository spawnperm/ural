# Домен: четыре контекста

Карта из [`projectDocs.ts`](../src/data/projectDocs.ts) (`BOUNDED_CONTEXTS`)
сопоставлена с кодом. Реализованы те контексты, у которых есть **поведение** —
правила, которые дорого нарушить. Остальные не созданы намеренно.

| Контекст | Файлы | Что защищает |
|---|---|---|
| **Приглашения** | `invitations/` | истечение и повторное погашение QR |
| **Прохождение** | `quest/` | подсчёт очков, начисление печатей |
| **Контент** | `content/` | жизненный цикл публикации персонажа |
| **Аутентификация** | `auth/` | матрица прав и маскирование поля |

## Почему не на каждый контекст по папке

В карте пять контекстов, реализовано четыре. `CalendarPlan` из «Контента» и
сущность `Visit` из «Приглашений» остались описаниями: расписание с датой и
визит с отметкой времени не имеют поведения, которое можно нарушить. Агрегат для
них был бы классом с геттерами.

Правило: **агрегат появляется вместе с первым инвариантом**, а не заранее.

## Что каждый контекст устранил

### Приглашения — два источника правды

```ts
interface InvitationRecord {
  expiresAt: string;   // когда истекает
  expired: boolean;    // ...и флаг
}
```

Флаг и дата расходились; UI верил флагу. Теперь `isExpiredAt()` вычисляется —
противоречие негде записать.

### Прохождение — три дефекта подсчёта

| Дефект | Как проявлялся | Что теперь |
|---|---|---|
| `correct` не проверялся | индекс за пределами `options` молча считался неверным | `Question.create` бросает |
| «из 3» захардкожено | четвёртый вопрос сделал бы счёт ложным | `attempt.totalQuestions` |
| пустой сценарий | `questions[0]` → `undefined` в рендере | `QuestAttempt.start` бросает |

Плюс правило печатей: `Math.max(1, correctCount)` писалось в месте вызова —
теперь это свойство агрегата.

### Контент — конечный автомат публикации

`draft → published → archived`, и обратно нельзя. Документация задаёт
`status: draft | published | archived`, но не говорит, какие переходы
допустимы; чтение API-примеров показало, что «снять с публикации» эндпоинта нет.
Архивирование черновика запрещено: у него нет опубликованных данных, так что это
удаление под другим именем.

### Аутентификация — правило, которое теряется в UI

> «User не может читать поле `correct` в question_sets.questions. Поле маскируется
> для роли User; проверка ответов выполняется воркером.»
> — `RBAC_SECURITY_RULES`

Маскирование на клиенте — это уже поздно: ответ уже в payload. `maskFields`
удаляет ключ до сериализации, а `mayReadField` возвращает **причину** отказа со
ссылкой на правило — так 403 в поле объясняется без чтения исходников.

Попутно: матрица оказалась не чисто CRUD — в ней есть `R + redeem`. Парсер
принимает и это, а тест перечисляет все реальные ячейки, поэтому новый формат
упадёт на тесте, а не в компоненте.

## Архитектурные границы

- **Агрегаты не знают инфраструктуры.** Ни NATS, ни Temporal, ни React: события
  копятся в буфере, публикует их прикладной слой.
- **События названы как в документации** — `CharacterPublished`,
  `QuestionSetUpdated`, `AnswerSubmitted`, `QuestCompleted`, `InvitationRedeemed`
  — чтобы таблица в документации и код говорили об одном.
- **Value objects общие** для контекстов (`DomainError`, `Instant` лежат в
  `invitations/`). Это Shared Kernel, который документация и так объявляет для
  аутентификации; выносить их в отдельный пакет до появления второго потребителя
  — преждевременно.
- **Репозиториев нет.** Состояние в `useState` компонента; интерфейс без
  реализации был бы моком.

## Что осталось за границей

- **`CalendarPlan`, `Visit`, `User`** — без поведения, поэтому без агрегатов.
- **Прикладной слой** — его роль исполняют обработчики компонентов.
- **Антикоррупционный слой** — нет внешней системы, с которой надо договариваться.
- **Хранилище** — Directus описан в документации, но не подключён в портале.

## Проверка

274 теста; покрытие домена: `auth` 100%, `content` 98%, `quest` 98%,
`invitations` 93%.

Тесты написаны как спецификация: для `content` — «легальный переход проходит,
нелегальный бросает», для `auth` — «код согласен с текстом `RBAC_MATRIX`»,
для `quest` — по тесту на каждый из трёх дефектов.
