# Первооткрыватели Прикамья — портал документации

Интерактивный портал технической документации и архитектуры проекта
**«Первооткрыватели Прикамья»** — AR-квеста по историческим дорогам Пермского края.

Одностраничное приложение на React, которое отдаёт Express-сервер. Помимо
контента портал умеет показывать состояние Git-репозитория и выполнять
коммит-пуш из интерфейса, поэтому серверная часть — не просто раздача статики.

## Быстрый старт

Требуется **Node.js 22.7+** (сервер запускает TypeScript через встроенное
удаление типов Node) и **pnpm 11**.

```bash
corepack enable          # включит pnpm из поля packageManager
pnpm install --frozen-lockfile
cp .env.example .env     # заполните своими значениями
pnpm run dev             # http://127.0.0.1:3000
```

Сервер по умолчанию слушает `127.0.0.1`, а не `0.0.0.0`: портал не должен быть
доступен из локальной сети без явного решения. Для контейнера или публикации
задайте `HOST=0.0.0.0`.

В production:

```bash
pnpm run build
NODE_ENV=production pnpm start
```

## Скрипты

| Команда | Что делает |
|---|---|
| `pnpm run dev` | Dev-сервер: Express + Vite в middleware-режиме, HMR |
| `pnpm run build` | Сборка фронтенда в `dist/` |
| `pnpm start` | Production-сервер: отдаёт `dist/` и `/api/*` |
| `pnpm run preview` | Предпросмотр собранного бандла силами Vite |
| `pnpm run lint` | `tsc --noEmit` в строгом режиме |
| `pnpm test` | Тесты на встроенном раннере Node (`node:test`) |
| `pnpm run test:coverage` | Тесты с покрытием и порогами (падает при регрессе) |
| `pnpm run check:env-docs` | Сверяет `.env.example` с переменными, которые реально читает код |
| `pnpm run clean` | Удаляет `dist/` и `coverage/` |

## Архитектура

```
server.ts                 точка входа: конфигурация, listen, graceful shutdown
src/server/               серверные модули (тестируются без запуска процесса)
  app.ts                  фабрика Express-приложения и порядок middleware
  config.ts               единственное место чтения переменных окружения
  gitService.ts           git через execFile, без shell; токен вне argv
  gitRouter.ts            маршруты /api/git/*
  validation.ts           валидация тел запросов
  rateLimiter.ts          скользящее окно для пишущего эндпоинта
  problemDetails.ts       ответы об ошибках по RFC 7807
  requestId.ts            X-Request-Id и корреляция логов
  securityHeaders.ts      заголовки безопасности и CORS
  shutdown.ts             корректное завершение по SIGTERM/SIGINT
src/shared/apiContract.ts типы запросов и ответов, общие для сервера и UI
src/components/           секции портала
src/data/                 контент документации и снапшоты версий
src/tests/                тесты: юнит, контрактные, интеграционные
```

Ключевое решение: `server.ts` — тонкий boot-скрипт, вся логика в `src/server/*`.
Так контрактные тесты поднимают приложение на эфемерном порту и не трогают
реальный репозиторий.

### Версионирование документации

Контент разбит на снапшоты в `src/data/versions/` (`v0.8`, `v0.9`, `v1.0`).
Переключатель версий меняет не только текст, но и набор секций: каждая версия
объявляет `includedSectionIds`.

## API

| Метод | Путь | Назначение | Ограничения |
|---|---|---|---|
| `GET` | `/api/health` | Статус, версия, uptime, ветка и SHA | — |
| `GET` | `/api/git/status` | Ветка, remote, изменения, последние коммиты | — |
| `POST` | `/api/git/commit-push` | Коммит и пуш текущих изменений | 5 запросов / 30 с на IP |

Все ошибки — `application/problem+json` по RFC 7807:

```json
{
  "type": "about:blank",
  "title": "Не настроен удалённый репозиторий origin.",
  "status": 400,
  "detail": "Не настроен удалённый репозиторий origin.",
  "instance": "/api/git/commit-push",
  "error": "Не настроен удалённый репозиторий origin.",
  "requestId": "6f1c…"
}
```

Коды: `400` — некорректное тело, `401` — для push нужен `GITHUB_TOKEN`,
`404` — неизвестный `/api/*`, `409` — в индексе оказался `.env`,
`429` — превышен лимит, `500` — внутренняя ошибка.

Типы запросов и ответов живут в `src/shared/apiContract.ts` и импортируются и
сервером, и UI: изменение формы ответа ломает сборку, а не рендер.

### Безопасность Git-панели

- Команды выполняются через `execFile` с вектором аргументов — shell не
  участвует, поэтому сообщение коммита не может стать командой.
- Сообщение, начинающееся с `-`, отклоняется: иначе git примет его за опцию.
- Токен передаётся git через одноразовый `GIT_ASKPASS`-скрипт, а не через
  `-c http.extraheader=…`: аргументы процесса читаются любым локальным
  пользователем через `ps`/`/proc`.
- Если в индекс попал `.env*`, коммит отменяется целиком (fail closed), а не
  «вычищается» — выборочное снятие с индекса оставляет варианты, о которых
  забыли.

## Развёртывание

### Docker Compose

```bash
cp .env.example .env      # при необходимости добавьте GITHUB_TOKEN
docker compose up -d --build
curl -s localhost:3000/api/health
```

Порт опубликован как `127.0.0.1:3000:3000`. Для публичного доступа нужен
reverse proxy с TLS — публиковать 3000 наружу не следует, у сервиса есть
эндпоинт, выполняющий `git push`.

### Проверка контейнера

```bash
docker compose ps                       # healthcheck должен стать healthy
docker compose logs -f --tail=50
docker compose exec app wget -qO- localhost:3000/api/health
```

Graceful shutdown проверяется `docker compose stop`: в логах должно появиться
`Received SIGTERM, shutting down gracefully`, а не мгновенное завершение.

## Качество кода

- **TypeScript strict** — `strict`, `noUnusedLocals`, `noUnusedParameters`,
  `noFallthroughCasesInSwitch`, `noImplicitOverride`.
- **Тесты** — `node:test` без внешних раннеров. Три уровня: юнит (валидация,
  лимитер, конфиг), контрактные (реальный Express на эфемерном порту) и
  интеграционные (настоящий git-репозиторий во временном каталоге).
- **Покрытие** — пороги в `test:coverage` (строки 70, функции 70, ветки 65).
- **CI** — `.github/workflows/ci.yml`: типы, `check:env-docs`, тесты с
  покрытием, сборка с бюджетом бандла, gitleaks и `pnpm audit`.

Локально перед коммитом достаточно:

```bash
pnpm run lint && pnpm test && pnpm run check:env-docs
```
