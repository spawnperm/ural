# Тестирование

Раннер — встроенный `node:test`, запускается через `tsx`. Внешних фреймворков
нет: для этого проекта они добавили бы конфигурацию и слой несовместимости, не
дав ничего взамен.

```bash
pnpm test                 # всё
pnpm run test:watch       # перезапуск при изменениях
pnpm run test:coverage    # с порогами покрытия
```

## Три уровня тестов

### Юнит

Не поднимают процесс и не трогают диск. Проверяют арифметику и ветвления:
`validation.test.ts`, `rateLimiter.test.ts`, `config.test.ts`,
`gitService.test.ts` (чистые функции редактирования и санитайзинга).

Правило: если тест требует сети или файловой системы — это не юнит.

### Контрактные

`apiContract.test.ts` поднимает настоящее приложение через `startTestServer()`
на эфемерном порту (`app.listen(0)`). Git-сервис подменён заглушкой, поэтому
реальный репозиторий не затрагивается.

Проверяется то, что видит клиент: коды ответов, `content-type`, заголовки,
форма problem+json, эхо `X-Request-Id`, лимит частоты.

```ts
const server = await startTestServer({ status: { branch: 'main' } });
const res = await fetch(`${server.baseUrl}/api/git/status`);
```

### Интеграционные

`gitService.integration.test.ts` создаёт реальный репозиторий во временном
каталоге и реальный bare-remote рядом с ним. Push выполняется по-настоящему —
просто локально.

Это важно: `gitService` целиком состоит из того, **как** он вызывает бинарник
git. Заглушка проверяла бы, что код вызывает сам себя. Настоящий git ловит
ошибки кавычек, refspec'ов и параметров askpass.

## Что проверяют тесты git-сервиса

- Коммит действительно доходит до remote (проверяется `git log` в bare-репозитории).
- Сообщение по умолчанию применяется, многострочное сворачивается в одну строку.
- Сообщение, начинающееся с `-`, отклоняется и не создаёт коммит.
- Force-added `.env` отменяет коммит целиком; ни индекс, ни remote его не
  получают.
- Push без токена на недоступный remote даёт 401-подобную ошибку.
- Токен не появляется в тексте ошибки.
- Временный каталог askpass удаляется даже после неудачного push.

## Покрытие

Пороги заданы в `package.json` (`test:coverage`): строки 70, функции 70, ветки
65. Gate падает при регрессе, а не печатает отчёт «для сведения».

Текущее покрытие серверных модулей — около 95% строк. Непокрытые участки —
ветки, требующие настоящего сбоя `listen` или другого uid, и они отмечены в
отчёте номерами строк.

## Чего в тестах нет и почему

- **E2E в браузере.** Портал — статический контент; визуальная регрессия
  ловилась бы скриншотами, а это отдельная инфраструктура. При появлении
  интерактивных форм это станет оправданным.
- **Тестов на `server.ts`.** Это скрипт запуска: чтение `.env`, `listen`,
  сигналы. Проверяется вручную по чек-листу из README и через `HEALTHCHECK`.

## Как добавить тест

1. Файл рядом с другими в `src/tests/`, имя `*.test.ts` (шаблон запуска —
   `src/tests/**/*.test.ts`).
2. Для HTTP — `startTestServer()` из `helpers/appHarness.ts`.
3. Для git — скопируйте `makeRepo()` из интеграционного файла: он создаёт
   изолированный репозиторий с remote и `.gitignore`.
4. Негативный кейс обязателен: покрывать только успех — значит не проверять
   обработку ошибок, где и живут дефекты.
